# Palletways delivery-depot dwell widget

Select **Palletways · At Depot 3> Days** from Customize Widgets. Restart the Python server after installation. Existing dashboard layouts are retained.

The background monitor checks up to 25 active Palletways orders per minute, oldest attempted check first, with a minimum 30-minute interval per order. It uses the configured PALLETWAYS_API_KEY and existing API request pacing. The dashboard refreshes the displayed cohort every minute while visible. Initial coverage takes multiple batches on large datasets; the widget footer shows a short condition summary; its hover text reports check progress and the oldest successful check.

A confirmed arrival requires DeliveryDepot to match the depot number in a VU/SCN/700 unloading-from-trunk event. A VU/SCN/700 scan naming the matching destination depot is accepted. A BAY/SCN/700 Inbound/Receive Scan is accepted only after a JIN/GDEP event identifies a vehicle bound for that destination depot. An inbound scan without that route evidence is excluded. Same-stay repeated unload scans and booking notes do not reset the timer. Normal delivery departure requires VL/SCN/800 with a depot number matching DeliveryDepot and a C&D vehicle description. Loading at another depot or other loading codes do not terminate the stay. Driver arrival and completion remain fallback closure evidence when the departure scan is missing; their timestamps are not presented as actual departure times. A subsequent confirmed unloading event begins a new stay.

Arrival timestamps are interpreted in Europe/London and stored in UTC. The threshold is strictly more than 72 elapsed hours including weekends. Results are ordered by oldest arrival first. Carrier-event time, not first observation time, starts the clock.

Missing or ambiguous evidence is excluded. API failures retain previous evidence and its successful check timestamp; the widget flags failed updates. A stored result describes the last successful carrier observation, not guaranteed real-time physical location. Arrival requires the verified destination-matching unload combination or the destination-bound route followed by its inbound scan; other codes alone do not establish arrival.
